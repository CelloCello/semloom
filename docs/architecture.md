# Architecture

Semloom is one TypeScript package in a pnpm workspace. Source boundaries separate responsibilities without requiring a package for each module.

A clean prepack build ships ESM/runtime declarations, docs and examples in a compiled tarball, without source maps or development files. `scripts/package-smoke.mjs` installs one real archive into isolated consumers to verify public exports and local browser-adapter paths. See [package installation and verification](releases.md).

- `src/core`: public data types, Registry, exported JSON Schema, semantic validation, deterministic IDs, Planner and CSS dependency/hash handling. It does not read report files or use browser APIs. Diagram semantic validation calls the Node-backed Pele parser; the complete compiler/validation entry is not browser-safe.
- `src/plugins`: twelve built-in kinds use the same `Registry.register()` manifest interface as local Plugins. Content schemas cannot redefine Core's `id`, `kind` or `sourceIds` envelope. The filesystem/module adapter resolves explicitly configured local modules; it does not install or discover packages.
- `src/html`: a central escaping template helper, document/sidebar composer and progressive navigation. `themes/` defines built-in tokens and fallback, `styles/` owns shared component rules and stylesheet composition, and `layouts/` owns page flow and responsive/print Layout rules. Core validates reference relationships; the composer adds block citations outside variant output.
- `src/cli`: argument/config parsing, bounded JSON input, diagnostics and atomic output replacement. Library `compile()` never writes files.

## Data and rendering

`compile(input, options, registry?, presentation?)` validates configuration and the document, clones input, resolves IDs, generates one Presentation Plan, and renders that plan. The returned HTML, resolved document and Explain plan describe the same selection. Registry freezes before compilation; schema/manifest copies prevent callers changing registrations through returned objects. Asynchronous `loadRegistry(paths, baseDirectory)` resolves all module exports first; Registry checks all definitions before resolving extensions, so extension order does not depend on config order.

Schema uses Ajv 8 in strict mode with no coercion, removal or default insertion. JSON Schema draft-07 provides a portable exported structural contract. Relationships such as unique IDs, reference targets and comparison field keys require a second semantic validation pass; they are documented rather than falsely advertised as pure JSON Schema constraints. Section recursion is represented by eight bounded definitions.

Default `compile()` calls share a private frozen built-in Registry. Public `createRegistry()` calls still return independent Registries, and explicitly supplied Registries retain their own Plugin definitions. A weak cache associates each frozen Registry with its private document Schema; validators are compiled lazily and reused by private Schema identity, including the fixed configuration and presentation-catalog Schemas. Each validation still checks the current input and builds fresh diagnostics. `documentSchema()` returns a deep copy, so exported Schema edits cannot change cached validation. Cache keys are objects rather than Plugin IDs, versions or the common document `$id`; unused custom Registries and their validators can be garbage-collected.

A validator that rejects input or throws is evicted before diagnostics are converted. This lets its complete Ajv error state, including referenced validators, be collected without waiting for another validation. The next use of that Schema recompiles its validator once; successful calls reuse it. Structural success followed by a semantic or rendering error keeps the validator cached, since those errors do not belong to Ajv's validation state.

Planner first checks support, then sorts descending scores with a code-point Variant-ID tie-break. It uses data size, field count and text length, never viewport or theme. An override can choose a lower-score compatible variant. IDs reserve every explicit Section/Block ID before allocating any automatic ID; source anchors have a separate reserved namespace.

`core/inline.ts` supplies a self-contained flat-run Schema and semantic validation; `html/inline.ts` renders validated runs with the escaping helper. The `richtext` kind uses these shared contracts without changing existing literal fields. After resolving all IDs, `resolveDocument()` validates aggregate inline text limits and checks links against the same `core/url.ts` policy and fragment rules used by source URLs. Future content kinds that accept runs must explicitly call the shared semantic validator for their run locations; arbitrary Plugin fields are not interpreted as inline content.

`core/hierarchy.ts` supplies the finite node Schema and total-node validation. Both Variants retain a complete nested list; tree is the default. Selected mindmaps add a Core-owned enhancement: `browser/hierarchy.ts` creates fresh escaped Markmap nodes, and `browser/mindmap.ts` adds keyboard/ARIA support, bounds and resource cleanup around Markmap’s geometry and folding. No-JS, setup failure and print use the complete SSR tree. See the [hierarchy contract](semantic-schema.md#hierarchy-content) for reader behavior and limits. Private Markmap declarations keep its upstream NodeNext incompatibilities out of public Node types.

`browser/mindmap-bundle.ts` synchronously bundles the pinned renderer and its local dependencies, caches the fixed runtime within a process, rejects external imports/unsafe script terminators and hashes the exact script for CSP. Resolved tree data and dependency licenses use a separately escaped JSON payload; authors' text never enters executable source. License collection follows contributing package files in both checkout and installed layouts, and includes d3-flextree already embedded upstream. Reports without a selected mindmap emit no Markmap script, payload or notices. No CDN or implicit remote loader is used.

Theme modules own the six-color mindmap palettes; `html/themes/index.ts` emits component variables and the renderer reads computed CSS. [Theme CSS](themes.md#hierarchy-branch-colors) controls colors without expanding semantic JSON or manifest token keys.

## Output and trust boundary

`core/list.ts` builds a bounded self-contained list Schema and checks total items and every nested item's inline content after ID resolution. The list renderer reuses `html/inline.ts`; list ordering is authored semantic data, not Planner inference. Code uses `pre`/`code` with escaped text and numeric CR references to prevent HTML parsing from normalizing CRLF/CR. The code Schema rejects NUL and unpaired surrogates, which cannot round-trip through UTF-8 HTML. Neither kind requires browser JavaScript.

The HTML always contains complete static content, CSS and a fixed navigation script. Optional interactive reports add one bundled switching script and safely encoded JSON for switchable blocks. No remote assets are required. The report works without JavaScript and includes print CSS. User strings are escaped in text/attribute contexts; fragments use a private WeakSet, so JSON cannot forge markup. Template indentation never trims interpolated data. Source URL rules are shared through the Node/browser-safe `core/url.ts`; semantic validation also checks source fragment targets. CSP authorizes scripts by the exact SHA-256 of navigation, any switching bundle and any selected Markmap/ECharts reader bundles. It permits inline styles but no remote resources or form submission. Document data never enters executable source. Plugins/adapters are trusted code, not a security sandbox.

Theme names and Layout names come from the shared core contract. The Planner receives locale/Layout, never Theme. `themes/index.ts` resolves token overrides against the minimal baseline, while `styles/index.ts` composes token CSS, shared components, document flow, sidebar overrides and print Layout resets in that order. Selected Plugin assets follow the combined Core stylesheet; Plugin-declared CSS remains with its manifest. Built-ins are explicitly imported modules. `core/presentation.ts` validates and clones external data definitions; `presentation/load.ts` explicitly loads local JSON/CSS before compilation. External Layout IDs are separate from their built-in base; Planner, Plugins and browser context receive that base. Selected external Theme CSS then Layout CSS follow Plugin assets; final Core print resets follow external CSS. See [presentation authoring](presentation-authoring.md) for paths, limits and cascade. The navigation script reads existing TOC links and heading IDs from the DOM, adds Scroll Spy, and progressively enables the mobile sidebar disclosure. Static navigation remains visible when JavaScript is absent or initialization fails. See [Themes and Layouts](themes.md) for adding Themes, focus, responsive and print behavior.

Output is deterministic for fixed inputs, code, dependencies and execution environment, including the Node version and platform. Byte-identical HTML across different Node versions or platforms is not promised; numeric SVG coordinates may differ. Atomic writes use a random temporary filename only, never a random value inside HTML. Compilation/validation happens before replacement; failures preserve old output and temporary files are cleaned.

`core/report-messages.ts` is the browser-safe catalog for built-in report UI. Server renderers, adapters and runtime controls share locale resolution; the original document locale remains in content/Plugin context. It does not translate authored data or affect built-in Variant scoring. See [report languages](localization.md) for fallback and accessibility behavior.

## Extension boundary

Plugin manifests separate `kinds` (content Schema plus initial Variants) from `extensions` (new Variants for an existing, exact data version). Registry checks Plugin/API/data versions, exact Plugin dependencies, duplicate IDs and schemas before reading a document. It validates all CSS declarations and dependency graphs, then emits only selected-Variant assets and their dependencies, ordered deterministically and deduplicated by content hash. The same asset ID with different content/dependencies is an error; contradictory ordering after deduplication is also rejected.

Manifest assets remain inline static CSS; browser modules use a separate optional descriptor. `src/browser/plan.ts` filters supported candidates by adapter capability; at least two are needed for switching. `bundle.ts` uses the [esbuild synchronous API](https://esbuild.github.io/api/#sync) to bundle required adapters into one browser IIFE without external imports. Disabling `interactive` skips Plugin switching adapters; a selected built-in mindmap still adds its independent Markmap bundle.

`src/browser/runtime.ts` preserves SSR during setup, builds incoming Views detached, rolls failed construction back to the old View and aborts registered partial resources. After a successful replacement it aborts/disposes the old View and runs all cleanups, isolating cleanup errors. It replaces only the View host, preserving Core citations, block/section IDs and navigation. Per-block frozen data and context never expose mutable input/config or Theme. Built-in comparison server renderers and browser adapters use the same pure templates; `semloom/browser` provides DOM-safe helpers without importing the compiler or Node APIs. The example Plugin follows the same contract. See [interactive reports](interactive.md) and [Plugin authoring](plugin-authoring.md).

## Chart and diagram pipeline

`core/chart.ts` and `core/diagram.ts` supply portable structural Schemas and shared semantic validation. The document pass enforces aggregate budgets. Diagram validation checks original source before Pele preprocessing can erase configuration, parses through its public API, then checks each supported model. No model/error cache is retained. Upstream DOM-bearing parser types stay private so main-entry consumers remain Node-only.

`node/` isolates synchronous lazy engine loading, notices and controlled SVG processing. ECharts 6.1.0 uses Node SVG SSR; Pele 1.13.0 renders checked source with host-owned links/images disabled and no resolvers. Ordinary documents do not initialize either engine. Core supplies resolved `blockId` separately from unchanged data. SVG processing restricts elements/attributes/URLs/styles, namespaces IDs and references by block/role/segment, and normalizes ECharts global renderer/class counters. Color-role attributes become CSS variables without replacing authored text.

`core/chart-presentation.ts` owns safe key mapping, data-derived domains, overflow-resistant coordinate scaling, wrapping and shared options. Fixed normalized bounds and tick intervals are constructed together from decimal steps. Every value axis supplies the public ECharts interval, bypassing automatic nice-extent calculation for fixed bounds across all ranges; overlap suppression controls label density while keeping the full-data scale. Bar print panels retain contiguous categories, all series and the full-data domain. Build-only layout errors preserve field pointers and CLI atomic writes; unexpected chart engine/SVG errors follow Core's standard renderer failure path. See the [layered data contract](semantic-schema.md#chart-content).

### Numeric axes

Bounds and intervals are calculated from all valid values in normalized engine coordinates. Nice endpoints share the interval's decimal step, retaining zero alignment in crossing domains and padding near numeric extremes. Any raw-domain metadata is converted separately and bounded to finite numbers. Reader series selection never recomputes the scale.

Line category tick density uses the available plot width and wrapped label widths. Value tick precision follows tick spacing, with space reserved for the resulting text; overlap suppression can omit labels without changing the domain. Tick formatting shifts the normalized value's decimal exponent as text, before floating-point multiplication could collapse distinct ticks near subnormal boundaries. It does not convert that text back to a Number. The SSR, print and browser paths share these options, keeping authored values unchanged.

### Mermaid restriction checks

`core/diagram.ts` checks original source, parses it with Pele's public API and inspects each supported model. Source-only statement checks use Pele's detected type; the later parse establishes syntax and the actual model. The scanner tracks quoted/escaped labels, comments and statement boundaries. ER attributes, class members and flowchart node/edge labels remain content scopes; namespaces and subgraphs remain statement scopes. Pipe/inline edge labels retain command-like text across solid, thick and dotted links; checks resume after their closing pipe or link operator. Names such as `rect`, `link` and `properties` remain identifiers where the grammar allows them, including sequence senders before arrows. Source is checked without rewriting it or adding another complete Mermaid parser.

| Restricted construct                                    | Source or public-model check in Pele 1.13.0                                                                                                                                   | Regression coverage                                                                  |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Frontmatter, initialization/config directives           | Original leading frontmatter and every `%%{`, before preprocessing can erase them                                                                                             | Empty/nonempty blocks and directives in labels/comments rejected                     |
| `style`, `classDef`, `linkStyle`, CSS class application | Statement boundaries; flow node/edge/subgraph styles/classes and defaults; class styleClasses/node styles; ER classes/entity/subgraph styles; state nested statements/classes | Actual statements rejected; ordinary member/label text accepted                      |
| Links/callbacks and sequence actor metadata             | Source `click`, `link`, `links`, `properties`; flow links, class links/callbacks, sequence actor links/properties, state links/nested click                                   | External link statements rejected; legal identifiers and message/label text accepted |
| Images/external icons                                   | Flow node img/icon fields; public model text for icon syntax                                                                                                                  | Shape metadata icons rejected                                                        |
| Math and HTML labels                                    | Public model text, including parsed/decoded labels                                                                                                                            | `$$…$$` and HTML elements rejected; ordinary comparison punctuation accepted         |
| Explicit sequence fills                                 | `rect` statement, box fill and rect-start message model                                                                                                                       | Named transparent groups accepted; color overrides rejected                          |

Sequence complexity uses each Pele message event once, including notes and group-control events. The separate `notes` collection is another representation of note events and is not added to that count. Nested state scopes are counted recursively. These semantic budgets are independent of the later print-layout limit. Source restrictions and count boundaries are exercised in `tests/charts-diagrams.test.mjs`; see the [author-facing diagram contract](semantic-schema.md#diagram-content).

### Reader integration

Selected `chart.svg` blocks add one trimmed ECharts SVG bundle, escaped data and LICENSE/NOTICE payload with an exact CSP hash. The reader retains SSR until successful setup, creates safe DOM tooltips and native keyed legend actions, measures local fonts and owns cleanup. Successful switching releases an enhanced initial View; failed construction retains it. Static print is independent of reader state. `chart.static` omits the reader engine; Pele never enters it. Theme-owned chart variables are separate from mindmap palettes and only accompany selected visual components.
