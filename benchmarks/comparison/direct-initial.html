選擇依據

本研究供 Semloom 的資料契約選型使用。 需要一般 union 與長度、範圍等驗證限制時，JSON Schema 較直接；若主要目標是跨語言型別與 tagged union，JTD 值得評估。這是依文件作出的選型判斷，不是速度測試結論。

能力比較

資料形狀與驗證能力
對象建模方式Union 支援限制表達主要取捨
JSON Schema以驗證限制定義可接受的資料支援 untagged union 與布林組合可描述數值範圍、字串長度與集合大小表達力較完整，規格與組合規則也較複雜
JSON Type Definition以固定 schema forms 定義資料形狀支援 tagged union；未標準化 untagged union限制能力較少，聚焦型別與資料形狀模型較簡單，適合型別產生、parser 與 serializer
