# Benchmarks

Benchmarks contain versioned, fixed inputs, comparison artifacts and reproducible methods. The [comparison scenario](comparison/README.md) covers a sourced technical report, a content edit, fixed/Auto presentation selection and a cards override.

Run from the repository root after installing dependencies:

```sh
pnpm benchmark
pnpm browsers:install
pnpm test:e2e
```

The benchmark command builds the compiler and writes timing/size measurements and HTML under `reports/benchmark/`. Browser tests add navigation measurements and screenshots there. This generated directory is ignored by Git; each run replaces its corresponding outputs. CI may retain it as an artifact.

The same semantic initial input also runs through minimal/sidebar, editorial/document and editorial/sidebar; the Auto condition supplies minimal/document. These cases measure the cost of rebuilding appearance and navigation, with the selected Variants recorded. Theme changes must preserve selections and content; timing differences alone do not measure reading quality. Browser coverage checks both complete Demos and the local Plugin across the Theme/Layout matrix.

Commit reusable scenarios, fixed baselines, runner code and methodology. A direct HTML file can be a fixed baseline even though it is HTML; it is an input to comparisons, rather than a report generated by the current compiler. Changes to a fixture should be reviewed as changes to the benchmark's task or expected content.

Per-run timings and environment snapshots are generated measurements, not portable performance thresholds. They are not dependencies of benchmark commands or tests. Measurements do not establish token savings or presentation-quality advantages without controlled, repeated evaluation.

The runner also measures interactive builds in minimal/document and editorial/sidebar. These include browser bundling and encoded switching data, so compare them with their static counterparts as different capabilities. Browser lifecycle tests exercise repeated switching, failed construction and cleanup. They do not measure independent Agent generation costs or human interaction quality.

[Additional report scenarios](scenarios/README.md) cover compact data, the six-kind PR daily report and wide multiline data. Each replays initial/edit tasks through fixed table, Auto and interactive Auto. These 18 additional conditions broaden content shapes; the original comparison's 14 conditions remain available separately. The `scenarios` result field and independent browser tests preserve facts/order/references rather than treating successful compilation as proof of fidelity.
